## Summary

First production release of the personal expense tracker — a solo, multi-currency, offline-first iOS + Android app built with React Native + Expo and backed by Supabase.

---

## Features by phase

### Phase 0 — Repo bootstrap
Expo TypeScript project with Expo Router, strict TypeScript, ESLint + Prettier, Jest, custom Geist font, and the full dependency tree committed.

### Phase 1 — Supabase schema
Postgres schema: `profiles`, `accounts`, `transactions`, `transfers`, `categories`, `budgets`, `recurring_rules`, `notif_parse_rules`, `merchant_rules`, `fx_rates`, `outbox`, `sync_state`. Last-write-wins trigger via monotonic `sync_version` (SQLSTATE `PT401`). Row-level security on every table.

### Phase 2 — Local SQLite + repositories
Encrypted SQLite via SQLCipher (key in Keychain/Keystore). Full repo layer for all tables with outbox enqueue + bump. Migrations runner. 30+ unit tests.

### Phase 3 — Sync engine
Custom outbox-drain + delta-pull engine. Supabase Realtime subscription for live updates. Conflict resolution: last-write-wins by `sync_version`. Offline-first: all writes go to SQLite first, drain to Supabase when online.

### Phase 4 — Auth + onboarding
Email/password sign-up and sign-in. Google OAuth (iOS + Android). Three-step onboarding: pick base currency → create first account → grant Android notification permission.

### Phase 5 — Manual entry MVP
Home dashboard with monthly totals, income vs. expense, and recent transactions. Quick-add sheet (amount, currency, category, account, note, merchant). Aurora gradient hero card. Undo toast with 5-second window.

### Phase 6 — Multi-currency + FX
LAK / THB / USD support. FX rates table seeded by Edge Function (exchangerate.host). Per-transaction FX override. Base currency conversion on dashboard and reports. FX rates management screen.

### Phase 7 — Accounts + transfers
Multiple named accounts with opening balances. Transfer between accounts (creates debit/credit pair). Running balance calculation. Account list with per-account totals.

### Phase 8 — Categories + merchant rules
Seeded default category set (editable). Merchant rule engine: regex → category + account auto-assignment. Rule tester with live extraction preview. Last-used category/account memory.

### Phase 9 — Reports + search/filter + export
Monthly pie chart, 12-month bar trend, savings rate gauge. Custom date range picker. Full-text search on note + merchant. Filter chips (date, category, account, amount, source, kind). CSV export (filtered). JSON backup + restore.

### Phase 10 — Budgets
Monthly per-category budgets with progress bars. 80% warning → local notification. 100% exceeded → push notification via Edge Function fan-out.

### Phase 11 — Recurring
Per-rule recurring transactions. `auto` mode: transaction created automatically on due date via Edge Function. `confirm` mode: local notification prompts user; confirm logs the transaction. Rule management screen.

### Phase 12 — Notifications (local + push)
Daily spending nudge (user-configurable, 8 PM). Budget threshold alerts. Recurring confirm prompts. Push token registration + Supabase storage. Push fan-out via Edge Function.

### Phase 13 — Receipts
Photo capture or gallery pick from transaction detail. Image compression (target <200 KB). Upload to Supabase Storage with offline queue. Thumbnail in transaction row. Full-screen viewer.

### Phase 14 — BCELOne notification capture (Android)
Kotlin `NotificationListenerService` exposed via Expo Modules. Notification parse rules (regex-based) with live tester UI. Auto-creates transactions from BCELOne push notifications. 5-second undo.

### Phase 15 — iOS share extension
Native iOS share extension (receives text from any app). Deep-links back to the app with prefilled amount/note. Documented setup in `docs/operations/ios-share-extension.md`.

### Phase 16 — Polish, observability, ship
Sentry integration (optional DSN via env). Ring-buffered local logs (1000 lines) + diagnostics screen (copy/share/email logs, outbox + sync stats). Settings hub (profile, base currency, about, sign out) in the More tab. Maestro E2E flows for five core paths. Icon/splash asset config + EAS build docs. This release note + acceptance checklist.

## Known limitations

- BCELOne notification format based on anticipated structure; production rule set is iterated from real samples post-launch.
- FX rates for LAK have limited market liquidity; per-transaction override is available.
- iOS does not support background notification capture (share extension is the substitute).
- Receipt OCR is not implemented; photos are stored as-is.
